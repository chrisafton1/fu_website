Privacy Policy

Last updated 18 August 2026

Short version: Gemma stores what your server configures and what you deliberately submit — applications, tickets, moderation records. She doesn't archive ordinary chat, doesn't sell anything to anyone, and everything lives on one machine the operator controls.

1. Who is responsible

Gemma is operated by a private individual ("the operator") and runs on hardware the operator owns. There is no company behind her and no third-party analytics, advertising or data-broker involvement.

Each server that adds Gemma decides what she does there. For most purposes the server's owners control the data in their community; the operator provides the software and the hosting.

2. What is stored

Everything sits in a single database file. By feature:

  • Server configuration — server ID, channel and role IDs you select, feature toggles and any text you write (welcome messages, autoresponses, application questions, ticket messages).
  • Applications — the answers submitted, the applicant's user ID, timestamps, the accept/deny decision, the reviewing staff member's ID and any note they leave.
  • Tickets — who opened it, when, who claimed it, and when closed a transcript of the channel: message text, author names and IDs, timestamps, embed titles and links to any files attached.
  • Moderation records — a numbered case per ban, kick, timeout, warning or purge, holding the target's user ID, the moderator's ID, the reason, duration and any evidence files uploaded by staff. Evidence is copied into the server's own log channel.
  • Highlight board — the message ID, channel, author ID and reaction count for messages that reach the threshold.
  • Reaction roles — which emoji maps to which role on which message.
  • Jail — who is jailed, by whom, why, until when, and the roles they had so they can be restored.
  • Server logs — if a server enables logging, deleted/edited message content, joins/leaves, role and channel changes are posted into that server's own log channels (they live in Discord, not in the bot's database).
  • Voice channels — which temporary voice channel belongs to whom, deleted when the channel is.
  • Ban network — if a server links to others owned by the same person, bans made there are copied to the linked servers, storing the banned account's ID, the reason, and which server it came from.
  • Global ban list — for accounts added to the shared list: the user ID, the reason shown to every participating server, a category, a link to the evidence, who added it and when, and any later pardon. Servers that enrol store which listed accounts they have banned or chosen to allow.
  • Protection features — anti-spam, anti-raid and anti-nuke keep short-lived counters in memory (a few seconds to minutes) and log the actions they take to the server's log channels.
  • Operational logs — errors and events written to log files on the host, which may include user IDs and channel IDs for troubleshooting. These rotate and are overwritten automatically.

Discord user IDs are numbers, not names. Display names appear where they're part of a transcript or embed.

3. What is not stored

  • Ordinary channel messages. They are read in the moment to check for autoresponder triggers or trap-channel activity, then discarded.
  • Direct messages between users, voice audio, or anything in servers Gemma isn't in.
  • Email addresses, passwords, payment details or IP addresses of Discord users.
  • Message content from channels the bot cannot see.

4. Why it's stored

Only to make the features work: remembering a server's settings between restarts, letting staff review an application, giving moderators a record with evidence, keeping the highlight board's counts accurate. There is no profiling, no advertising, and no sale or sharing of data.

5. How messages are handled

Gemma uses Discord's Message Content intent so autoresponders and the trap channel can work. That means she receives the text of messages in channels she can see. Nothing is written down unless a feature specifically requires it — a matched autoresponder produces a reply, not a stored record; a ticket transcript is only created when a ticket is closed.

6. How long it's kept

  • Configuration — until changed or the bot is removed from the server.
  • Applications, tickets and moderation cases — indefinitely, so staff can look back, unless deleted on request or by a server manager using the bot's own commands.
  • Backups — encrypted-at-rest copies are not made; snapshots of the database are kept on a rolling basis (most recent set only) and older ones are deleted automatically.
  • Log files — rotated and overwritten within roughly 30 MB of activity.

Removing Gemma from a server stops all processing for that server. Stored data for it may remain in the database and in existing backups until deleted on request or overwritten as backups rotate.

7. Who can see it

  • Your server's staff — anything posted into your log, review or transcript channels. Set those channels' permissions accordingly.
  • The operator — has technical access to the database and logs, and will only look when necessary to fix a problem or respond to a request.
  • Discord — everything travels over Discord's platform and is subject to Discord's own privacy policy.
  • Nobody else. No third-party processors, no analytics services, no sale, no sharing — unless legally compelled, in which case only what's required.

8. Security

The bot runs on a private machine with no inbound ports open to the internet; it connects out to Discord rather than accepting connections. Credentials are kept in a permission-restricted file outside the database, and backups exclude them. Access is limited to the operator.

No system is perfectly secure, and this is a hobby project rather than an audited service. Don't put anything in a ticket or application you'd be seriously harmed by exposing.

9. Your choices & requests

Depending on where you live you may have rights to access, correct or delete personal data about you. Regardless of location, you can ask for the following:

  • See what's held about you — a copy of your applications, tickets and moderation records in a given server.
  • Deletion — removal of your applications, ticket transcripts, highlight-board entries or moderation cases.
  • Correction — fixing something inaccurate.

Start with the server's own staff, since they can delete applications, tickets and cases directly with the bot's commands, and they control the channels transcripts were posted to. If that isn't possible, contact the operator (below) — include the server and roughly when it happened. Requests are handled on a best-effort basis, usually within 30 days.

One limit worth stating plainly: moderation records exist so a community can enforce its rules, and a server may decline to delete a case about you while it remains relevant. Copies already posted into a server's log channel are that server's messages, and only its staff can remove them.

10. Children

Gemma is not directed at children. You must meet Discord's minimum age for your country to use Discord at all. If the operator learns that data from someone below that age has been stored, it will be deleted on request.

11. This website

These pages are static and hosted on Cloudflare Pages. There are no cookies, no tracking pixels and no analytics. Fonts are loaded from Google Fonts, which receives your IP address as part of serving them. The status page fetches a small JSON file describing the bot's health; it contains counts and feature names only, never user data.

12. Changes

This policy will change as the bot does. The "last updated" date above always reflects the current version, and significant changes will be announced in the support server where practical.

13. The global ban list

This one deserves its own section, because it's the only place Gemma shares information about a person between servers that don't otherwise know each other.

What it is

A list of Discord account IDs, maintained by the bot's operator, of accounts confirmed to be automated (bots) or to friend-add members in order to solicit them, including NSFW solicitation. Each entry records the account ID, a written reason, a category, a link to the evidence, and who added it. Nothing else about the account is stored — no message history, no profile data.

How it's used

Servers choose to enrol. In an enrolled server, a listed account that joins is sent a direct message explaining the ban and giving an appeal link, and is then banned. Servers can override any individual entry, and can leave the list at any time.

Appeals and removal

Anyone listed can appeal at the appeal server. A successful appeal removes the entry everywhere, and participating servers can undo the resulting bans with a single command. You may also request removal of your data by contacting the operator directly. Entries are kept while they remain relevant; pardoned entries keep a record of the pardon so servers can see the account was cleared.

The limits of it

This list is not used for interpersonal disputes, individual servers' moderation decisions, or anything a moderator simply disagreed with. Any server enrolling in it is trusting the operator's judgement; any server can stop at any time.

14. Contact

For privacy questions or data requests, contact the operator through the support server or by direct message on Discord.
